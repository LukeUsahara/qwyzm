# Phase 11

権威 WebSocket のカスタム部屋。対戦ゲームループ本体は Phase 12。

## 目的

部屋の作成・参加・ロビー・時刻同期を用意し、2 クライアントが同じ RuleSet で開始直前まで到達できるようにする。ゲーム規則の正本はサーバー側の `game-core` 実行（Phase 12）に渡し、ここでは部屋状態だけを権威にする。

## 含むもの

1. `apps/signaling` を権威 WS サーバーへ転用（WebRTC は使わない）
2. 6 文字の部屋コードと URL / コード参加
3. ロビー（参加者一覧、ホストのルール変更・キック・開始）
4. 再接続トークン
5. `server_time` ping/pong による `offsetMs`（既存 `offsetFromProbe`）
6. WS メッセージの Zod スキーマ
7. 構造だけの部屋画面。ホームのカスタム部屋を有効化

部屋はメモリ上。永続化しない。ゲストの `local:` 問題セットは部屋では使えない（公式セットまたはジャンル指定のみ）。

## 含まないもの

- 早押し試合そのもの（Phase 12）
- ランダムマッチ、WebRTC、ボイス、観戦
- 部屋の DB 永続化
- ゲストセットの共有

## 完了条件

- 2 クライアントが同室に入り、同一 RuleSet を共有し、開始直前まで到達
- ホスト以外はルールを変えられず、キックできる
- 切断後にトークンで同じ席へ戻れる
- lint / typecheck / test / build が緑
